# 改进方案模板（含字段约定）

## 字段约定（每条建议必含）

| 字段 | 说明 |
|---|---|
| 编号 | `QW-x` Quick Win / `SM-x` Strategic / 副站 `XX-x` |
| 描述 + 操作步骤 | 问题是什么 + 具体怎么做（分①②③） |
| 负责方 | `SEO自助`（无需开发）/ `需开发`（+人天预估） |
| 漏斗节点 | 流量获取 → 着陆页 → 下载 → 注册 → 付费 |
| 预期信号 + 层级 | 哪个数据往哪动；L1(1-4周)/L2(1-3月)/L3(3月+) |
| 验证 | 用什么数据/工具确认（不全标"待补"） |
| 成本 | 低 / 中 / 高 |
| 来源 | `[材料]` / `[实诊]` / `[补充]` / `[质疑]` |

## 文档结构

1. **如何使用本文档**（字段约定 + 见效分层）
2. **诊断总览**：材料 × 实诊校准表（坐实/新发现/乐观点）
3. **Quick Wins（1-4 周）**：按 影响面 × 见效速度 排序，技术底座类优先
4. **Strategic Moves（1-3 月+）**：内容/工具/外链/区域化等长效资产
5. **副站 Top 3-5**（如有）
6. **验证、监控与迭代**：L1/L2/L3 三层 + 监控基线 + 滚动节奏
7. **附录**：关键词库 + 待补数据清单 + 来源标注说明

## 单条示例

```markdown
### QW-1 修复 Core Web Vitals（头号项）[材料][实诊]
- [ ] **问题**：CrUX Failed；TTFB 实测偏慢（如 2.x s，good<0.8s、竞品更快）；Lighthouse 性能分偏低。
- **操作**：① 降 TTFB（SSR 缓存/CDN）；② 首屏 JS 瘦身；③ 图片 WebP+懒加载+显式宽高；④ 配合减少跳转层级。
- **负责方**：需开发（前端+后端），预估 5-8 人天
- **漏斗节点**：全漏斗（排名底座）
- **预期信号**：TTFB→<0.8s、LCP→<2.5s、CrUX Failed→Passing
- **验证**：GSC「核心网页指标」、PSI
- **成本**：中　**层级**：L1→间接抬 L2
```

## 排序原则

- Quick Wins 内部：技术底座（影响全站）> 模板级修复（影响一类页）> 单页优化。
- 要"快速业务结果"时，额外优先**已有流量但转化差**的页（CRO+SEO，最接近 L3 见效）。
