# SPEC 模板

> 环节 1 苏格拉底澄清后产出。固化需求，再动手分析/出方案。

```markdown
# SPEC：<站点> SEO 诊断与改进方案

> 版本 v1.0 · 日期 <date> · 输入：<材料/域名>

## 0. 背景与工作模式
- 交付物：<单份 Markdown / Excel / PPT>
- 工作模式：<一次性 / 滚动迭代>
- 站点范围：<主站完整 + 副站快诊?>
- 材料处理：<优先采纳可质疑，标注来源>

## 1. Problem Statement（问题陈述）
<核心矛盾一句话> + 分层证据：
- 业务层：<低质页占比/核心词缺位/品牌占比…>
- 技术层：<性能/跳转/sitemap/标签…>
- 内容/权威层：<E-E-A-T/外链…>
- 机制层：<跨岗位评估口径…>

## 2. Proposed Solution（方案描述）
- 框架：<Topic Cluster + 三阶段 / 其他>
- 双档优先级：Quick Wins（1-4 周）+ Strategic Moves（1-3 月+）
- 每条字段化：描述/操作/负责方(自助or需开发+工作量)/漏斗节点/预期信号/验证数据/成本/来源
- 滚动迭代：每轮回填数据动态调整

## 3. Technical Constraints（技术约束）
- 执行模式：<SEO 主导+开发排期?>
- 数据基线：<边做边补?每条附验证数据需求>
- 可改动范围：<工具页算本体?架构能不能大动?>
- 多站/多语言约束：<hreflang/独立站>
- 材料信任源：<采纳为主线，补充/质疑标注>

## 4. Non-goals（明确不做）
- <付费广告 / 产品改动 / 蹭热点 / 整站重构 …>
- 不夸大见效（见 §5 分层）

## 5. Success Criteria（成功标准）
- 业务目标：<全漏斗转化提升>
- 双层验证：
  | 层级 | 时间窗 | 指标 |
  |---|---|---|
  | L1 立刻见效 | 1-4 周 | CWV/收录/抓取/CTR/页面健康度 |
  | L2 中期 | 1-3 月 | 核心词排名、自然流量质量 |
  | L3 业务结果 | 3 月+ | SEO 归因下载/付费 |
- 诚实约束：业务转化位于漏斗末端，不会 2 周突变。
- 产物自身：可分配 / 可跟踪 / 可取舍 / 优先级清晰 / 来源可追溯。
```
